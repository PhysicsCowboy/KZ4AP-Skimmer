# Race a small LSTM against a duration HMM

The decoder to build and benchmark first is not one algorithm but a pair on a shared test bench. Start with a cheap fix to the current baseline: re-center each station precisely on its frequency, then filter to the element bandwidth *before* the envelope detector and make its outputs soft. Then run two candidates head to head. The first is a small streaming CNN+LSTM network trained with CTC (connectionist temporal classification), following VE3NEA's open-source DeepCW recipe. The second is a Bell-style explicit-duration hidden Markov model (HMM) decoder with a Kalman-tracked amplitude. The only controlled comparison in the whole literature favors the neural option. It is VE3NEA's own 2024 test of a roughly 375,000-parameter CNN+LSTM against his closed-source CW Skimmer, run on identical synthetic data. The network matched Skimmer near threshold and beat it clearly under fast fading and hand keying. At 1 Hz Doppler spread, +17.8 dB key-on SNR in 500 Hz, and paddle keying, Skimmer's character error rate (CER) was 11.1% and the network's was 3.5%. The HMM path has weaker evidence: AG1LE's port of Bell's 1977 decoder showed a roughly 3% CER floor and was unstable. It still deserves a slot because it has an explicit timing model, costs little per channel, and is the natural back end for a hybrid in which a network supplies soft key-on probabilities. Every published sensitivity figure for steady (non-fading) noise, once converted to this project's convention, lands within a few dB of 0 dB key-on SNR in 500 Hz. The differences among them are smaller than the uncertainty in how each author defined SNR. So published headline numbers cannot pick the winner. Only the project's own benchmark, with fading, poor fists, speed changes and interference (QRM), can.

**Evidence labels.** Each claim carries one of three labels. **[fact]** means documented by the primary source: the author's code, manual, thesis or blog. **[secondhand]** means reported by a third party, or taken from a summary of a source that was not read line by line. **[inference]** means reasoning by the research team or by this report. Tables abbreviate these as F, S and I. No claim here was independently reproduced unless it says "measured."

## Glossary

This survey uses machine-learning and statistical-decoding terms without defining them in the body. They are collected here, for a reader who knows DSP and detection theory but not ML training practice. Where a DSP or detection-theory analogy exists, it is given, but the analogy is a way to build intuition, not a claim that the two are mathematically identical.

- **Neural network.** A function built from layers of simple units, each forming a weighted sum of its inputs and then passing it through a fixed nonlinearity, connected in series (and, for a recurrent network, with feedback). Read it as a large, structured nonlinear filter whose numerical coefficients are set by fitting to data rather than by a signal model.
- **Parameter / weight.** One of the network's numerical coefficients, analogous to a filter's tap coefficients. A "375,000-parameter" model has that many independently adjustable numbers.
- **Training.** Adjusting a network's parameters, usually by gradient descent on a loss function that scores how wrong its output is on labeled examples, so as to reduce that loss. It is curve fitting with millions of free parameters and iterative, gradient-based updates, rather than a closed-form solution or a handful of Newton steps.
- **CNN / convolutional layer.** A layer that slides a bank of small, learned 2-D (or 1-D) filter kernels across its input — here, a time-frequency image — and passes each filter's output through a nonlinearity. It is a bank of learned FIR-like filters followed by a pointwise nonlinearity, except the coefficients come from training data instead of a signal model, and several filters ("channels") run in parallel on the same input.
- **Nonlinearity / activation function.** The fixed, pointwise nonlinear function (commonly ReLU, max(0, x)) applied after each layer's linear step. Without it, stacking layers would collapse algebraically to one linear operator; with it, the network can represent the kind of nonlinear decision boundary a threshold detector already has, but shaped by data instead of derived from a noise model.
- **RNN (recurrent neural network).** A network with a hidden state updated one time step at a time from the current input and the previous state — the same shape as a discrete-time state-space or IIR recursion, but with a learned, generally nonlinear update rule instead of fixed linear coefficients.
- **LSTM (long short-term memory).** An RNN cell design with a separate memory ("cell state") and several learned multiplicative gates that control what gets written in, kept, and read out. It is a recurrent state-space update with learned gains, like a Kalman filter's state propagation, except the gain terms are learned nonlinear functions of the input rather than derived from a noise model.
- **GRU (gated recurrent unit).** A simplified LSTM with fewer gates and no separate cell state; the same role at lower cost, usually with similar performance.
- **Bidirectional.** An RNN run twice on a sequence, once forward in time and once backward, with both passes combined so each output depends on past and future context. This needs the whole sequence in hand first, so it is not causal and not streaming.
- **Streaming (as used here).** A decoder that processes samples in one causal pass, without needing future input beyond a small, fixed look-ahead, so it can emit output as data arrives — as opposed to a batch or offline decoder that runs on a whole recording at once. A bidirectional network, or one with symmetric (non-causal) convolutions, is not streaming unless restricted to run causally.
- **Attention.** A mechanism that computes, for each output position, a weighted average over some set of input positions, with the weights themselves learned functions of the data rather than fixed by position. Loosely, an adaptive, content-dependent correlator that decides on the fly which parts of the input matter for the current output, in place of a filter's or RNN's fixed-lag structure.
- **Transformer.** A network architecture built mainly from stacked attention layers, rather than convolution or recurrence, interleaved with pointwise nonlinear layers. Strong at long-range context, but in its plain form needs the whole sequence at once and is not naturally streaming.
- **Conformer.** A hybrid speech-recognition architecture that interleaves convolutional layers (local, short-range structure) with attention layers (long-range context) within each processing block.
- **CTC (connectionist temporal classification) and its blank symbol.** A training loss and decoding scheme for a network that emits output frames faster than the target has symbols, where the alignment between frames and symbols (which frames correspond to which character) is unknown. CTC adds an extra "blank" output meaning "no new character here," and trains by summing the probability over every frame-to-character alignment consistent with the target text (collapsing repeated non-blank symbols and discarding blanks). It is analogous to summing over all the possible timing offsets of a detection problem instead of committing to one.
- **Beam search.** An approximate search that keeps only the k best-scoring partial output hypotheses at each decoding step (the "beam width" k) and extends each of them, rather than exploring every possible output sequence. It is the same pruned-tree idea as the search Bell's decoder and manta's `hsmm` run over hypothesis paths, applied here to a network's output probabilities instead of a Kalman-filtered likelihood.
- **Greedy decoding.** The k = 1 special case of beam search: at each step, keep only the single highest-probability symbol and move on without reconsidering it. Cheap, but can commit early to a locally good, globally wrong choice.
- **RNN-T / transducer.** A streaming-friendly alternative to CTC that pairs an audio encoder with a separate label-predicting network and jointly scores audio frames against output symbols one at a time, allowing more than one output token (or none) per input frame, without CTC's assumption that frames are conditionally independent given the alignment.
- **Language model.** A model of which symbol or word sequences are likely, independent of the acoustic evidence, used to bias decoding toward plausible text. It plays the role of a prior distribution over messages — the same role Skimmer's callsign-pattern validation or a code-structure rule plays elsewhere in this survey.
- **n-gram.** A simple language model that scores a sequence by the probability of each symbol given only the preceding n − 1 symbols, with those probabilities estimated by counting occurrences in a text corpus. A 3-gram (trigram) character model predicts the next character from the previous two.
- **Spectrogram (as used here).** A time-frequency image formed from the magnitude (or log-magnitude) of a short-time Fourier transform — the same STFT/FFT-bin representation this project's channelizer already produces, consumed here as a 2-D image by a CNN instead of as complex bins by a filter.
- **MFCC (mel-frequency cepstral coefficients).** A hand-engineered feature computed from a spectrogram by warping its frequency axis to a perceptual ("mel") scale, taking a log, and then taking a discrete cosine transform to decorrelate and compress the result. A speech-recognition-specific feature transform, largely superseded here by feeding a plain spectrogram to a CNN, which can learn an equivalent or better transform from data.
- **ONNX / ONNX Runtime.** ONNX (Open Neural Network Exchange) is a portable file format that stores a trained network's architecture and weights independent of the framework (PyTorch, etc.) used to train it. ONNX Runtime is software that loads and executes an ONNX file efficiently on CPU or GPU. "Exporting to ONNX" means freezing a trained model into this portable, deployable form.
- **Quantization / int8.** Reducing the numeric precision used to store and compute a network's weights and activations, typically from 32-bit floating point down to 8-bit integers, for a several-fold cut in memory and compute cost at the price of a usually small accuracy loss. The deployment analog of using fixed-point instead of floating-point arithmetic in a DSP implementation.
- **MAC / GMAC / FLOP.** A MAC (multiply-accumulate; see the Symbols table above) is one multiply plus one add, the basic operation of a filter tap or a matrix-vector product; one MAC is conventionally counted as two FLOPs (floating-point operations). A GMAC/s is a billion MACs per second, the unit this survey mostly uses for a network's compute cost per channel, directly comparable to the Mflop/s figures given for Bell's Kalman-filter decoder.
- **Epoch / batch.** One epoch is one full pass of the training procedure over the entire training dataset. Training data is normally split into smaller batches, with the network's parameters updated after each batch rather than after every individual example, both for computational efficiency and to average out noise in the gradient estimate.
- **Overfitting.** A model whose parameters have fit the specific training examples, including their noise and idiosyncrasies, rather than the underlying pattern, so that performance on new, unseen data is much worse than on the training data. The ML analog of fitting a high-order polynomial through noisy points that tracks the points beautifully but predicts poorly off them.
- **Held-out set / validation set.** Data deliberately withheld from training and used only to measure how well a model generalizes to examples it has not seen, exposing overfitting that training-set accuracy alone would hide. This survey also uses "held-out" for a recording or operator excluded from a model's fine-tuning data, to test performance on a case the model never saw.
- **HMM (hidden Markov model).** A statistical model of a system that steps through a sequence of unobserved ("hidden") discrete states under fixed transition probabilities, where each state produces an observation through a known emission distribution. This is exactly Bell's and manta's keying model: the hidden state is the element/letter/speed context, the observation is the filtered amplitude, and decoding infers the most likely state sequence from the noisy observations.
- **Viterbi algorithm.** The exact, efficient dynamic-programming method for finding the single most likely hidden-state sequence through an HMM given a sequence of observations. It keeps only the best path into each state at each time step, rather than enumerating every path, and traces the winning path back at the end.
- **Semi-Markov / explicit-duration HMM.** An HMM variant in which each state has its own explicit duration distribution (for example, Bell's Laplacian or manta's log-normal element-length model), replacing the ordinary HMM's implicit, memoryless (geometric) assumption about how long a state persists. This matches Morse timing, where dit and dah lengths cluster tightly around known nominal ratios rather than following a memoryless distribution.
- **Kalman filter.** The optimal recursive linear estimator for a linear-Gaussian state-space model: it propagates a state estimate and its uncertainty (covariance) forward in time and updates both whenever a new noisy observation arrives. Used throughout this survey to track a signal's amplitude, or its I/Q pair, through noise — one hypothesis, or one HMM path, at a time.
- **Rician / Rayleigh distribution.** The probability distributions of an envelope (magnitude) after quadrature (I/Q) detection: Rayleigh describes the envelope of noise alone (key-up, no signal), and Rician describes the envelope of a constant signal plus noise (key-down). Deciding key-up versus key-down from one envelope sample is exactly deciding which of these two distributions it more likely came from; see the MAP-threshold discussion below.
- **CER (character error rate).** Defined in the Symbols table above: the Levenshtein edit distance between decoded and reference text, divided by the reference length.
- **WER (word error rate).** The same edit-distance measure as CER, but computed with whole words as the unit instead of characters, so one wrong character anywhere in a word counts as one whole-word error.

## One SNR yardstick shrinks the published gaps to a few dB

Morse SNR figures in the literature use at least five noise bandwidths (2000, 2500, 3000 and 500 Hz, plus "the signal bandwidth"). They also use two definitions of signal power: key-on power, and power averaged over keying. For white noise and a signal lying inside both bandwidths, the conversion to this project's convention is S₅₀₀ = S_B + 10·log₁₀(B / 500 Hz) + K. Here K = 0 dB for key-on definitions, and K = −10·log₁₀(d) ≈ +3.0 dB for power averaged over keying at d ≈ 0.5 [inference]. The project already adopts key-down power over noise in 500 Hz for its synthetic recordings. Its channel filter has a noise bandwidth of 252 Hz, so SNR in the channel is S₅₀₀ + 3.0 dB ([signal-processing.md](../signal-processing.md)) [fact]. CW Skimmer uses the same convention for spots. VE3NEA's own description is that the signal is taken through a 50 Hz filter with key-off and transition samples discarded, and its power is estimated under a Rayleigh fading model. The noise density is taken from the flat part of the spectrum across the whole receiver bandwidth and multiplied by 500 Hz ([RBN blog, VE3NEA email, 2014](http://reversebeacon.blogspot.com/2014/03/understanding-signal-to-noise-ratio-snr.html)) [fact]. The manual calls it "the key-on signal-to-noise ratio in the 500 Hz bandwidth averaged over QSB" ([CW Skimmer manual](http://dxatlas.com/CWSkimmer/Files/CwSkimmer.pdf)) [fact]. One difference remains. The project's S₅₀₀ is a generator setting, known exactly, while RBN's is an estimate built up over about 45 s. Because RBN's noise floor is band-wide rather than local, its SNR reads high in crowded or splattered segments ([RBN blog 2014](http://reversebeacon.blogspot.com/2014/03/understanding-signal-to-noise-ratio-snr.html)) [secondhand for the 45 s figure; inference for the bias].

A second yardstick links SNR to detection theory. For a key-on SNR S (linear) in bandwidth B, the dit energy over noise density is E_s/N₀ = S·B·T [inference: definitional algebra]. At 25 WPM (T = 48 ms), **S₅₀₀ = 0 dB means E_s/N₀ ≈ 13.8 dB per dit**. The same S₅₀₀ gives 11.8 dB at 40 WPM and 17.0 dB at 12 WPM. A typical RBN spot of about +5 dB (the manual's examples show 4–7 dB) therefore carries roughly 19 dB of energy per dit at 25 WPM. That is far from any detection limit, so the competition between decoders is fought at S₅₀₀ ≈ 0 dB and below, and under fading and bad timing [inference]. The research notes quoted, from unchecked textbook memory, "something like 12–14 dB E_s/N₀" for noncoherent on-off keying (OOK) near 10⁻³ symbol error. Checked against Proakis, the figures for a hard on/off decision on one element in AWGN, with a matched filter and a carrier phase unknown but constant over the element, are [fact for Proakis's general formulas, eqs. 4.2–37 (p. 175) and 4.5–21 (p. 213); the OOK numbers are derived from them and computed in proakis-ook-notes.md §2.6, since Proakis leaves noncoherent OOK as a homework problem]:

| Per-element error probability (entries: key-on E_s/N₀, dB re 1) | Coherent | Noncoherent, optimum threshold | Noncoherent, threshold at half the key-down amplitude |
|---|---|---|---|
| 10⁻² | 10.3 dB | 11.4 dB | 12.0 dB |
| 10⁻³ | 12.8 dB | 13.5 dB | 14.0 dB |

All entries are **key-on** E_s/N₀ in dB relative to 1. Read as average energy per element (E_avg/N₀), each is 3.0 dB lower; for example 10.5 dB rather than 13.5 dB. So the quoted 12–14 dB is right for key-on energy and 3 dB too high for average energy. The noncoherent penalty is 0.7 dB at 10⁻³ and grows to 1–2 dB at 10⁻² to 10⁻¹, where a CW decoder actually works (proakis-ook-notes.md §2.6) [fact for the derived numbers]. At S₅₀₀ = 0 dB and 25 WPM (E_s/N₀ ≈ 13.8 dB per dit), an ideal noncoherent per-dit hard decision is therefore already near 10⁻³ error, but only if the filter is matched to the dit and the station is centered on it (see the frequency-offset caveat under the Bell 1975 discussion) [inference].

**The optimum threshold is not at the midpoint.** For OOK the maximum a posteriori (MAP) threshold is where the prior-weighted Rayleigh (key-up) and Rician (key-down) envelope densities cross (Proakis eq. 4.5–21, p. 213; §4.1–1, pp. 162–163) [fact]. For equal priors it lies about 44–45% of the way from the key-up mean envelope to the key-down mean envelope at E_s/N₀ = 10–14 dB, and it moves with SNR; key-down being less likely than key-up raises it slightly (proakis-ook-notes.md §2.3) [inference: derived from Proakis's densities].

Read side by side, the steady-noise entries cluster tightly. fldigi's matched-filter slicer reaches 1.2% CER at S₅₀₀ between −2.2 and +0.8 dB, depending on PathSim's undocumented definition. e04's roughly 3.6-million-parameter network reports under 8% at 0 dB and under 1.5% at +2 dB. They are also confounded by speed, which moves E_s/N₀ by several dB at fixed S₅₀₀. **No published AWGN curve demonstrates that any decoder is more than about 3 dB better than a well-filtered hard-decision slicer on machine-timed code** [inference]. The large, well-measured differences appear only in VE3NEA's fading and hand-keying grid. That is where the project's benchmark must look.

## CW Skimmer is a closed Bayesian target with documented spotting rules

Afreet's only published description of the decoder is one phrase: "a very sensitive CW decoding algorithm based on the methods of Bayesian statistics" ([manual](http://dxatlas.com/CWSkimmer/Files/CwSkimmer.pdf); [product page](https://www.dxatlas.com/CwSkimmer/)) [fact]. The single technical hint is a private email VE3NEA sent to AG1LE. It advised expressing prior knowledge as probabilities and updating them with data: compute the probability that the signal is present rather than deciding at every sample, and carry probabilities "all the way to the word recognition unit." In that email VE3NEA also said he spent about eight years and tried hundreds of algorithms ([AG1LE, Jan 2013](http://ag1le.blogspot.com/2013/01/towards-bayesian-morse-decoder.html)) [fact, relayed]. Circumstantial evidence fits a soft-decision pipeline. Low-confidence characters print in pale colors. A release note cites improved "word segmentation." The SNR estimator classifies samples as key-on, key-off or transition ([manual](http://dxatlas.com/CWSkimmer/Files/CwSkimmer.pdf); [RBN 2014](http://reversebeacon.blogspot.com/2014/03/understanding-signal-to-noise-ratio-snr.html)) [fact]. That the internals resemble an HMM or particle filter is an informed guess, not a documented fact [inference]. Whether a dictionary prior is used inside the decoder was speculated by AG1LE and a commenter but never confirmed ([AG1LE 2013](http://ag1le.blogspot.com/2013/01/towards-bayesian-morse-decoder.html)) [secondhand].

The architecture is better documented than the algorithm. Skimmer creates one decoder per CW signal found in the passband, with up to **700 parallel decoders on a 3 GHz Pentium 4** and an "Adaptive" decoder count that follows available CPU ([manual](http://dxatlas.com/CWSkimmer/Files/CwSkimmer.pdf)) [fact]. RBN administrators describe each decoder as about 50 Hz wide with a 256-character history ([RBN "How to get spotted"](https://www.reversebeacon.net/pages/How+to+get+spotted+by+the+RBN+44)) [secondhand]. The 50 Hz width agrees with the 50 Hz extraction filter VE3NEA describes for SNR [fact]. Dividing 3×10⁹ cycles/s among 700 decoders bounds the whole per-decoder budget, shared overhead included, at about **4.3 million CPU cycles per second of signal** on a 2000s-era CPU. That is the best available existence proof that a probabilistic decoder can be cheap enough for hundreds of channels [inference from a vendor claim].

Spotting is a separate, mostly rule-based layer. A message analyzer extracts callsigns and keywords (CQ, DE, TEST, later also FD, SS, NA and UP). A call must then pass pattern validation against Skimmer Server's patt3ch.lst file, whose patterns use @ for a letter and # for a digit, and repeat enough times within the 256-character buffer ([RBN 2021](http://reversebeacon.blogspot.com/2021/09/how-skimmer-server-decides-what-to-spot.html); [N6TV CTU 2018](https://www.contestuniversity.com/wp-content/uploads/2018/05/4.-N6TV-CW-and-RTTY-Skimmers-and-the-Reverse-Beacon-Network.pdf)) [secondhand, from discussion with VE3NEA]. The repeat thresholds are:

| Validation level | Watch list | Common ("+") pattern | Listed pattern | Unlisted pattern |
|---|---|---|---|---|
| Minimal | 1 | 2 | 2 | 2 |
| Normal | 1 | 2 | 3 | 5 |
| Aggressive | 2 | 4 | 4 | not spotted |
| Paranoid | 2 | not spotted | not spotted | not spotted |

Source: [RBN 2021](http://reversebeacon.blogspot.com/2021/09/how-skimmer-server-decides-what-to-spot.html) [S]. A simpler RBN page gives 2/3/4 repeats, which differs on the unlisted count [S].

Skimmer Server does not use the MASTER.DTA super-check-partial file, although standalone Skimmer does. It will not re-spot the same call near the same frequency within 10 minutes. Busted calls are caught mostly downstream, by CT1BOH's unpublished cross-skimmer statistics ([N6TV CTU 2018](https://www.contestuniversity.com/wp-content/uploads/2018/05/4.-N6TV-CW-and-RTTY-Skimmers-and-the-Reverse-Beacon-Network.pdf); [RBN tutorial 2013](http://reversebeacon.blogspot.com/2013/12/a-new-tutorial-on-using-rbn.html)) [secondhand]. The table behaves like a crude posterior threshold: prior plausibility is traded against the number of independent decodes. A decoder with calibrated soft scores could replace it with an explicit callsign posterior [inference].

Skimmer's known weaknesses are timing-related. Sender guidance asks for constant speed within a message, 3:1 weighting and clean spacing without half-spaces next to the call ([RBN 2021](http://reversebeacon.blogspot.com/2021/09/how-skimmer-server-decides-what-to-spot.html); [RBN page](https://www.reversebeacon.net/pages/How+to+get+spotted+by+the+RBN+44)) [secondhand]. In an informal side-by-side test on live QSOs, judged by ear with no error counts and no stated band, speed or SNR, G4ILO found MRP40 more accurate than Skimmer. He reported that Skimmer ran words together and then put a space in the middle of a word, sometimes added a spurious E at the start of a word, lagged behind MRP40, and would not decode unless tuned exactly onto the signal ([G4ILO blog](http://blog.g4ilo.com/2012/12/best-morse-decoder.html); g4ilo-2012-notes.md §2) [fact that he reported this; the observations themselves are one listener's anecdote]. The research notes had credited G4ILO with saying Skimmer excels on weak signals. **That was a misattribution.** The weak-signal opinion comes from a commenter, PC4T, who disagreed with G4ILO, and he gave no measurement (g4ilo-2012-notes.md §3). No controlled CER-versus-SNR benchmark of Skimmer exists except VE3NEA's own 2024 comparison, discussed below.

## Hard decisions throw away what pre-detection filtering could keep

The project's baseline belongs to the oldest family of Morse decoders. Gold's MAUDE (MIT Lincoln Laboratory, 1959) and Guenther's PDP-12 program (Air Force Institute of Technology, 1973) classified mark and space durations after a hard on/off decision. MAUDE did it in two stages. First, fixed rules that need no threshold: over a sliding window of 6 spaces, the longest is taken as a character or word space and the shortest as a space within a character; the shortest of 6 marks is taken as a dot; and an "alphabet test" uses the fact that only a minority of 4- to 6-mark patterns are valid Morse characters. Only the elements these rules leave unresolved are then classified against thresholds set a fixed offset above exponentially weighted running averages of the logarithms of mark and space durations (Gold 1959, pp. 18–20; gold-1959-notes.md §2.2) [fact]. Guenther's rules were: a mark longer than the average is a dash, a mark shorter than half a dot is discarded as noise, and runs of characters with no gap are re-split at the largest internal space ([Guenther transcription](http://alanpich.github.io/Morse-Code-Recognition/computer-recognition-program/program-description/code-translation-section.html)) [fact]. Gold's abstract says MAUDE decoded "between 90 per cent and 95 per cent of 184 operators," but the body of the paper defines the test as **184 messages from 53 operators, about 45,000 characters** (p. 22) [fact]. The percentages are the share of messages with under 6% character errors, a cutoff Gold himself calls a crude guess: 89.1% with the threshold offsets fixed for each operator and 96.2% with offsets recomputed every 100 marks or spaces in an IBM 704 simulation (Table IV, p. 23) [fact]. No SNR, noise condition or receiver appears anywhere in the paper, so the input was most likely a clean keying signal [inference] ([IEEE Xplore, Gold](https://ieeexplore.ieee.org/abstract/document/1057478/); gold-1959-notes.md §2.4). Gold's "elementary properties of language" amount to one rule, justified by the rarity of five or more successive E's or T's in English. For the 12 operators who sent all three kinds of text, MAUDE's character error rates on English, letter-cipher and number-cipher text were about the same (1.12%, 0.99% and 1%; Table III, p. 22), so that rule made no measurable difference in his test [fact for the table; inference for the conclusion]. fldigi is the modern version. Its chain is:

1. An FFT low-pass filter, optionally "matched" at 5×WPM/1.2 Hz.
2. A moving-average envelope about half a dot long.
3. Normalization by an automatic gain control (AGC) and a noise-floor tracker, with decay constants of roughly 200 ms up and 1000 ms down.
4. Upper and lower hysteresis thresholds.
5. A speed tracker fed only by adjacent dot–dash pairs whose length ratio is between 2 and 4.
6. A single dit/dah split, followed by table lookup.

AG1LE's self-organizing-map (SOM) codebook match is an optional replacement for the table lookup ([fldigi cw.cxx](https://github.com/w1hkj/fldigi/blob/master/src/cw_rtty/cw.cxx)) [fact]. His July 2012 eHam article on the SOM prototype (a 7×7 map trained on 14 characters) is a demonstration only and reports no error rate or SNR ([eHam 28435](https://www.eham.net/article/28435); neural-papers-notes.md §2) [fact]. Its measured cliff runs from 1.2% CER to 50.7% over just 5 dB ([AG1LE 2013](http://ag1le.blogspot.com/2013/01/morse-decoder-snr-vs-cer-testing.html)) [fact]. That is the signature of one flipped or split element corrupting a whole character [inference]. The SOM always returns *some* character and printed "garbage" in noise ([AG1LE 2012](http://ag1le.blogspot.com/2012/05/fldigi-more-test-results-on.html)) [fact]. ggmorse fits speed and threshold by exhaustive search over a window, which assumes one speed and one threshold per window ([ggmorse source](https://raw.githubusercontent.com/ggerganov/ggmorse/master/src/ggmorse.cpp)) [fact; the consequence is inference]. PA3FWM's RSCW performs a Viterbi-like maximum-likelihood search, which its author calls optimal for on-off keying in AWGN. It works only with machine-perfect timing and publishes no SNR figures ([RSCW](https://www.pa3fwm.nl/software/rscw/algorithm.html)) [fact].

E. L. Bell's work at the Naval Postgraduate School is the central classical reference. It is also the clearest evidence on **filtering before versus after the envelope detector**. In his 1975 thesis, post-detection smoothing on a 2 kHz input needed about +6 dB (2 kHz) for about 10% letter error. Adding a 100 Hz band-pass *before* detection moved that point to about −7 dB. A pre-detection Kalman filter tracking the in-phase and quadrature (I/Q) pair gave about 1% bit error at −14 dB (2 kHz) ([Bell 1975](https://archive.org/stream/processingofmanu00bellpdf/processingofmanu00bell_djvu.txt)) [fact]. (This pre-detection I/Q filter belongs to the 1975 thesis only. The 1977 dissertation, below, works on the post-detection envelope.) Detection theory explains the direction of this. With no signal the envelope is Rayleigh-distributed, and with a signal present it is Rician (Proakis eqs. 2.3–43 and 2.3–56, pp. 48–50) [fact]. The optimum noncoherent receiver correlates with, that is matched-filters, the expected element and only then takes the envelope (Proakis eqs. 4.5–23/24 and Fig. 4.5–1, p. 214) [fact]. That is the textbook argument for filtering before detection. A second, commonly given mechanism is that at low input SNR the noise×noise term dominates a square-law or envelope detector's output and suppresses the weak signal ([Univ. of Michigan EECS 555](http://www.eecs.umich.edu/courses/eecs555/chap5.pdf)). Proakis does not analyze this small-signal suppression; the nearest passage is the squaring loss of a carrier-recovery loop (§5.2–5, pp. 311–312), so the mechanism stays **[inference]** (proakis-ook-notes.md item 6). Bell's 13 dB shift came from narrowing a 2 kHz input by a factor of 20 (10·log₁₀ 20 = 13.0 dB), where the detector input sat far below 0 dB SNR. In 1977 Bell himself estimated that his fixed 100 Hz filter cost 6 dB at 50 WPM and 10 dB at 20 WPM relative to a filter matched to the element, and kept it wide only to tolerate about 50 Hz of chirp (Bell 1977, pp. 111–112) [fact: Bell's estimate, not a measurement]. The project's detector already sees only 252 Hz (noise bandwidth), where the input SNR is S₅₀₀ + 3.0 dB. A dit-matched pre-filter with a noise bandwidth of 1/T ≈ 21 Hz at 25 WPM (exactly 1/T for a rectangular element; proakis-ook-notes.md §2.7) would narrow the noise by a further 10·log₁₀(252/21) ≈ 10.8 dB at the detector input. The realized CER gain will be smaller than that, because the baseline's post-detection smoothing (a first-order filter with τ = ¼ dit) already recovers part of it. **The gain should be measured, not assumed** ([signal-processing.md](../signal-processing.md)) [inference].

**A narrow pre-filter needs the station centered on it.** The noncoherent detector ignores a constant carrier phase but not a frequency offset comparable to 1/T. Correlating a tone offset by Δf (Hz) against a template of duration T scales the amplitude by |sinc(Δf·T)|, with sinc(x) = sin(πx)/(πx) (derived from Proakis eq. 4.5–28, p. 215) [inference: derived]. Today the channelizer centers each station on the nearest FFT bin, so a station can sit up to ±11.7 Hz off center ([signal-processing.md](../signal-processing.md), section 7). With a dit-matched filter that offset costs up to **5.1 dB of signal power at 25 WPM** (T = 48 ms) and **8.8 dB at 20 WPM** (T = 60 ms), relative to a centered station. It erases about half (25 WPM) to most (20 WPM) of the predicted 10.8 dB, and drift during a transmission adds to it (proakis-ook-notes.md item 15) [inference: derived]. The wide 252 Hz channel filter is insensitive to such offsets, because they fall in its flat passband. So a narrow pre-filter requires each station to be re-centered by a fine frequency estimate, and tracked for drift, to within a small fraction of 1/T (for example ±2 Hz, a 0.2 dB loss at 20 WPM) before filtering [inference]. Bell also found that the Viterbi code model helped only when the bit error was already below about 3%. At 35 WPM and +6 dB (2 kHz) it cut bit error from 0.83% to 0.35%, and at +4 dB it gave nothing ([Bell 1975](https://archive.org/stream/processingofmanu00bellpdf/processingofmanu00bell_djvu.txt)) [fact]. **Most of the sensitivity comes from the soft front end, not from the sequence model** [inference].

Bell's 1977 dissertation generalized this into optimal Bayesian estimation. The keying process is a memory-conditioned Markov process with keystate, position within the letter, letter context, and a speed "control" variable. It is observed through a Gauss–Markov fading amplitude. The optimal decoder is "a denumerable but exponentially expanding set of linear Kalman filters operating on a dynamically evolving trellis," and it was tested only on random letters ([Internet Archive abstract](https://archive.org/details/optimalbayesiane00bell)) [fact]. The details below are from the page images (bell-1977-notes.md) [fact unless marked]:

- **Observation.** Not I/Q. The input passes a fixed 100 Hz band-pass filter and an envelope detector, is sampled at 200 samples/s (τ = 5 ms), and has its noise-floor mean subtracted. The result is treated as Gaussian with variance 2μ_n², where μ_n (in normalized amplitude units) is the mean noise envelope, although it is really Rayleigh or Rician (pp. 110–114, 123–124).
- **Filters.** Each hypothesis carries one **scalar** Kalman filter on the received amplitude, observed only during marks; its innovation gives that hypothesis's likelihood. There is no phase or frequency state (pp. 76, 109–118).
- **State and timing model.** The discrete state is (letter-tree node, element type of 6, key state, time in the current element, speed). Speed is an integer from 10 to 60 WPM and changes only at element boundaries, in steps of ±2/±4 WPM after marks and element spaces and larger steps after word spaces and pauses. Element durations, normalized by the dit length at the hypothesized speed, have a Laplacian (two-sided exponential) density about the nominal 1, 3, 7 or 14 dits, applied in hazard form (pp. 96–104; bell-1977-notes.md §2.2).
- **Search.** Every sample, each saved path extends into at most 30 successors (6 element types × 5 speed steps). Pruning keeps the best path for each element type, then adds paths in decreasing probability until they hold 0.9 of the probability, with at most 25 paths (8–16 on average). Paths are not merged, so this is a pruned tree rather than a Viterbi trellis. Characters are released at the common ancestor of all paths, or forced at 1 s of delay (pp. 119–123, 131–132).
- **Results.** The idealized synchronous decoder reached about 2% letter error at E/N₀ = 12 dB, where E is the key-on energy per dot, against a lower bound of about 0.7% (Fig. 14, p. 128; read by eye). The original research notes relayed, as a low-confidence secondhand claim, "about 10⁻⁵ letter error at about 12 dB E_b/N₀". **That claim is false.** Nothing in the thesis goes below about 0.1% letter error. The 10⁻⁵ figure is probably Table IV's single-element (on/off) detection error for envelope detection at S₁₀₀ = 12 dB, 2×10⁻⁵ at 50 WPM (p. 35) [inference about its origin]. The realistic decoder, simulated at 20 WPM, gave 3–8% letter error at S₅₀₀ = −1 to −3 dB for keyboard sending and good-to-fair fists (13–14% for a poor fist), and a cliff to 31–38% at −4 dB (Tables XV–XVI). On nine off-air recordings at S₁₀₀ = 16–22 dB (S₅₀₀ = 9–15 dB), letter error was 1–15%. The failures came from static and weak interfering signals, which the model has no way to represent (pp. 141–143).
- **Cost.** On a PDP-10, 1 minute of signal took about 20 minutes (p. 140). Scaled to a modern implementation, the pruning statistics imply about 150–400 scalar Kalman steps per sample, **about 2–3 Mflop/s per channel** (millions of floating-point operations per second) at about 200 samples/s, and 8–10 Mflop/s in the worst case of 25 × 30 extensions (bell-1977-notes.md §4, §8) [inference].

Bell names the open problems himself: adapting to the individual fist, a language or format model, an adaptive pre-detection filter to recover the 6–10 dB, and correct envelope statistics (pp. 66, 93, 106–114, 145–146). AG1LE hand-entered Bell's Fortran into about 3,335 lines of C with Bell's verbal permission. It has six keystates, per-path Kalman likelihoods, Bayesian path updates and an 8–80 WPM speed tracker ([AG1LE Part 1](http://ag1le.blogspot.com/2013/09/new-morse-decoder-part-1.html); [Part 2](http://ag1le.blogspot.com/2013/12/new-morse-decoder-part-2.html)) [fact]. The results were mixed. He reported "significant accuracy improvement" over fldigi on real noisy signals. He also recorded an unexplained roughly 3% CER floor, a noise estimator that did not track, intermittent overflows, and a speed estimator that could stick at its limits. A 2014 multi-channel build decoded nine signals but lost accuracy when several stations at different speeds were present ([Part 2](http://ag1le.blogspot.com/2013/12/new-morse-decoder-part-2.html); [Part 6](http://ag1le.blogspot.com/2014/07/new-morse-decoder-part-6.html)) [fact]. AG1LE's port reports an 8–80 WPM speed range, wider than the 10–60 WPM in Bell's thesis and code. Its instabilities, noise-estimator trouble and CER floor point to parameters and implementation. Note that Bell's own text and Fortran disagree on several constants (the duration spread, the amplitude model and the noise-estimator windows; bell-1977-notes.md §7), which a port must resolve one way or the other [fact for the disagreement; inference for its relevance]. The multi-station degradation, however, matches Bell's own field failures, which point to a gap in the model: it has no interference or impulse-noise state [inference]. These are the engineering risks a Bell-style decoder carries. Its cost, about 2–3 Mflop/s per channel from Bell's measured pruning statistics, fits inside Skimmer's inferred budget, but it is an estimate, not a measurement [inference]. No Morse-specific particle filter has been published. A Rao–Blackwellized particle filter with continuous speed and amplitude integrated out by a Kalman filter is untested design territory [inference].

**manta's `hsmm` is a modern, tested explicit-duration decoder, and the only one scored on a real recording** (manta-notes.md §3–4) [fact unless labeled]. manta (Tony Hagale, 2026, MIT OR Apache-2.0, version 0.1.0 with no releases) runs one decoder per signal on 375 samples/s channels of a polyphase filterbank with 93.75 Hz spacing and 82.2 Hz noise bandwidth, passing only the magnitude to the decoder. Its opt-in `hsmm` decoder is a semi-Markov segment decoder with token passing, close to this survey's option 3:

- **Evidence.** The amplitude is smoothed over 8 ms and normalized between a noise level (a per-track running minimum over 1.5 s, raised by a measured +2.16 dB power ratio to remove the minimum's low bias) and a mark level (a sliding maximum over ±4 dits). The per-sample LLR is (û − 0.5)/σ_u² with σ_u = 0.30, where û is the normalized amplitude (dimensionless): a **Gaussian, not Rician** likelihood with a spread that ignores SNR.
- **Timing model.** Log-normal element durations (standard deviation of ln(duration) 0.22, admitted within 0.6–1.5 × nominal), rather than Bell's Laplacian; segments start and end only at keying edges, so cost scales with edges rather than samples.
- **Speed.** Each token carries its own dit length, updated per element within 8–60 WPM and seeded at 5 speeds; beam of 12 tokens; commit on a common prefix or after 25 dits.
- **Correlated evidence.** It sums per-sample LLRs at 375 samples/s although the channel's noise correlation time is about 1/(82.2 Hz) ≈ 12 ms ≈ 4.6 samples, so its evidence is overweighted by about 4–5× against its priors: the caveat under option 1 below [inference].

manta's real-signal benchmark is an **oracle**: in a real recording (15 min of 192 kS/s I/Q, 2025 CQ WW CW, 40 m), open a channel at the frequency of each RBN spot by the skimmer K5TR and decode a 40 s window around it, bypassing the detector. A window scores **as_word** if the spotted call appears as a whole decoded word, **framed** if that word follows CQ, DE or TEST, and **substring** if the call appears anywhere. Over 221 windows `hsmm` scored 56.1% as_word, 31.7% framed and 58.8% substring, against 26.7%, 13.1% and 48.0% for manta's threshold-keyed `legacy` decoder. By the RBN-reported SNR of each spot (below 15, 15–25 and at least 25 dB; presumably CW Skimmer's key-down S₅₀₀, which manta does not state [inference]), `hsmm` as_word was 24%, 58% and 65%. Since K5TR copied every call, `hsmm` recovers about half of what CW Skimmer copied from the same band at another receiver [inference]. The same decoder failed manta's own acceptance gate (3 of 9 synthetic "real-conditions" vectors passed; a strong pileup vector decoded 0 of 34 signals), costs about 3.5 ms of CPU per track-second on an Apple M4 Pro, 4.25× its own budget, and has no published CER-versus-SNR curve. This is the first real-recording evidence for a duration-model decoder since Bell's nine field recordings. It shows that such a decoder doubles a threshold-keyed decoder's whole-call recall on real contest traffic, but it is not a controlled comparison against a neural decoder or against CW Skimmer on common data.

## Small streaming networks win where timing and fading break the model

Neural Morse decoders have converged on an automatic-speech-recognition pattern: a spectrogram, a small convolutional front end, a recurrent or Conformer encoder, and CTC training ([VE3NEA/DeepCW](https://github.com/VE3NEA/DeepCW); [AG1LE 2020](https://ag1le.blogspot.com/2020/04/new-real-time-deep-learning-morse.html); [morseformer](https://github.com/sderhy/morseformer)) [fact]. The most important entry is VE3NEA's DeepCW (October 2024, MIT license). It has two 3×3 convolutions with pooling, a Dense(64) layer and a **stateful LSTM(256)** feeding a softmax over 43 classes. That comes to **about 375,000 parameters**, and the model is rebuilt for batch-1 streaming with greedy CTC decoding. Its input is a 22-bin crop at 11.7 Hz spacing (about 258 Hz) at 93.75 frames/s ([VE3NEA/DeepCW model.ipynb](https://github.com/VE3NEA/DeepCW)) [fact]. The geometry maps exactly onto this project's channel. At r = 1500 samples/s, a 128-point FFT gives 1500/128 = 11.72 Hz bins, and a 16-sample hop gives 93.75 frames/s. The notebook's 50 ms window becomes 75 samples, zero-padded [inference]. Its training generator is the most principled found:

- **Text:** character and word statistics drawn from CW Skimmer decodes of real band traffic.
- **Fading:** Rayleigh fading with f_D = 0.1–3 Hz.
- **SNR and speed:** SNR from −16 to +50 dB (key-on, 3 kHz) and speed from 8 to 50 WPM.
- **Keying:** log-normal element timing for each keying style, with a mix of 25% hand key, 50% paddle and 25% computer.
- **Transmitter faults:** a random key-on/off imbalance.

Source: [VE3NEA/DeepCW data_generation.ipynb](https://github.com/VE3NEA/DeepCW) [fact]. Training ran at 80–100 ms per batch on a GPU. With 329 batches per epoch over 50 epochs, that implies under half an hour of GPU time [inference from documented figures]. The research notes do not record whether pretrained weights ship with the repository.

VE3NEA benchmarked it against CW Skimmer on about 30,000 characters per point ([accuracy_charts.ipynb](https://github.com/VE3NEA/DeepCW)) [fact]. SNRs are converted to S₅₀₀ by adding 7.8 dB [inference]. Each cell gives CER as Skimmer / DeepCW:

Three patterns stand out [inference]. First, under slow fading the two are equal to within a few percent, and **the network is worse at 12 WPM**. The small network buys no raw sensitivity. Second, Skimmer's error rate stays near 40% at 3 Hz Doppler spread even at +27.8 dB. That is a model-mismatch floor, not a noise floor, and the network removes most of it. Third, hand keying leaves both decoders with a 6–8% floor at high SNR, so timing variability remains unsolved. One caution: this is the network's author running his own generator. The test data share a distribution with the training data, and no real recordings were scored. The notes also raise the possibility that VE3NEA's CER excludes spaces, which would hide the segmentation errors that dominate real-audio failures [inference].

The other neural entries sharpen that caution. e04's DeepCW is an ONNX model of about 3.6 million parameters. Its operators, with self-attention and no LSTM, suggest a Conformer-like encoder ([deepcw-engine](https://github.com/e04/deepcw-engine)) [measured by the research team from the ONNX graph; the architecture label is inference]. Its README claims the table figures in AWGN only, with an unpublished training recipe. On three YouTube QSO clips it made fewer character errors than CW Skimmer, fldigi and ggmorse, mostly failing on run-together words, and the author disclaims this as a general ranking ([README](https://raw.githubusercontent.com/e04/web-deep-cw-decoder/main/README.md)) [fact]. morseformer (sderhy; code April–June 2026, v0.6.4; Apache-2.0 for code and weights) is a **4.13 million-parameter** bidirectional Conformer with CTC and RNN-T heads; the shipped decode path is greedy RNN-T, and an optional character 3-gram word splitter runs only in the offline "prose" preset ([morseformer](https://github.com/sderhy/morseformer); morseformer-notes.md §2) [fact; the parameter count was measured from the checkpoint]. An earlier version of this survey quoted about 3.9 million parameters, which is the encoder plus CTC head alone, and led with its **17.75% CER** on 26 real hand-keyed ragchew clips (31 minutes). That headline needs two corrections. It is the unweighted mean of per-clip CERs, spaces included, not a character-weighted total. And it averages 8.45% on operator set g3ses, whose recordings were also used in the real-audio fine-tune, with **28.6% on the held-out operator g6pz**. The held-out 28.6% is the honest real-audio figure. The corpus is unpublished and its SNR is not stated, so neither number can be placed on the S₅₀₀ axis (morseformer-notes.md §6) [fact for the numbers and the data paths; inference for which figure is honest]. A GPT-style language model was switched off because "it hurt amateur jargon" [fact]. AG1LE's 2020 CNN-LSTM-CTC misread characters that straddled frame boundaries, confused numbers, and learned no word spaces ([AG1LE 2020](https://ag1le.blogspot.com/2020/04/new-real-time-deep-learning-morse.html)) [fact]. Across every real-audio report, **the dominant failure is spacing and segmentation on hand-sent code, not tone detection** [inference].

The academic entries, now read in full, add no usable CER-versus-SNR evidence. The IEEE 2023 "LSTM-CTC" paper (Win and San) is MFCC features into a single bidirectional LSTM with CTC and no convolutional front end, trained on clean synthetic clips of one or two words at 5 WPM. It defines no SNR, reports no CER or word error rate, and its headline 95% training accuracy comes with 4% validation accuracy, the worst of its three runs: plain overfitting (neural-papers-notes.md §1) [fact for the numbers; inference for the diagnosis]. Wang et al. 2018 is not an end-to-end network at all. It is a speech-recognition pipeline comparing HMMs with Gaussian-mixture (GMM) or deep-neural-network (DNN) state likelihoods, recognizing whole words from 2020 synthetic clips. Its best result is 1.1% word error rate (WER) for the DNN-HMM at an SNR of 8 dB, the training SNR, rising to 18% at −3 dB. For both figures the paper states neither the noise bandwidth nor whether the signal power is key-on or averaged, so neither converts to S₅₀₀. The vocabulary size is not stated either, and a small closed word set is likely (wang-yfdm-notes.md §a) [fact for the numbers; inference for the vocabulary]. YFDM (Wei, Li and Han 2023) is not a decoder. It is a modified YOLOv5s object detector that draws boxes around Morse bursts in 640×640 spectrogram images spanning 2 MHz (about 3 kHz per pixel), trained and tested on synthetic data with "−5 to 0 dB" background noise, reference and bandwidth not stated. It reports precision and recall near 0.99 but no result broken out by SNR and no false-alarm rate, at 72 images/s on a desktop RTX 3080 Ti GPU (wang-yfdm-notes.md §b) [fact]. Whether a detector like it could serve as a front end for this project's per-hop CPU detector ([signal-processing.md](../signal-processing.md), section 6) is unproven; adopting one would mean a GPU or NPU and batched images instead of streaming [inference].

A closer reading of morseformer fills in what its README leaves out (morseformer-notes.md) [fact unless labeled]:

- **Not streaming.** Attention is unmasked, the depthwise convolutions are symmetric (±120 ms of look-ahead per layer), the front-end filter is zero-phase and normalization is per window. It runs as a 6 s sliding window re-decoded every 2 s, committing only the central 2 s of each window, so text lags the audio by up to 4 s. A truly streaming version would need retraining [inference].
- **Input.** A single feature channel: a 200 Hz-wide band-pass around a 600 Hz tone at 8000 samples/s, the log of the envelope, 500 frames/s, z-scored per window. Because our channel is already the analytic signal around the station, the same feature is a ±100 Hz low-pass on the 1500 samples/s complex baseband, then magnitude, log and a 3-sample mean. That route matched the 8 kHz path with correlation 0.994–0.999 and gave identical decodes on one synthetic message [measured, one message and one seed].
- **Output.** 49 tokens including an explicit word-space token, so word spaces come from the network, not from timing. The only prosigns are `=` for BT and `+` for AR; SK, KN and BK come out as ordinary letter pairs.
- **Training.** Synthetic clips at **16–28 WPM only**, with sinusoidal QSB up to 15 dB deep at up to 1 Hz (no Rayleigh fading), one CW interferer 8–18 dB below the wanted signal in a quarter of clips, and a real-audio fine-tune. Its SNR ρ is measured against white noise over 0–4000 Hz with a peak-selecting signal estimate that jumps with duty cycle, so ρ converts to S₅₀₀ (key-on, 500 Hz) only within a band of roughly ρ + 7 to ρ + 17 dB [inference, from the code]. No SNR curve is published for the shipped checkpoint.
- **False output on noise.** About one false character per 6 s of pure noise in the author's own gate test, which multiplies across hundreds of channels [fact for the rate; inference for the consequence].

Three more GitHub repositories were checked, and none adds CER evidence (github-repos-notes.md) [fact unless labeled]. **pd0wm/nn-morse** (2020, MIT) is a Dense×4 → LSTM(256) → CTC network with **no convolution**, about 740,000 parameters, on a 21-bin linear-power spectrogram (50 Hz bins, 50 frames/s at 2000 samples/s real audio). Its structure could stream, and weights ship. Its generator has rectangular keying and no fading, QRM or QRN, and it never goes below **S₅₀₀ = +1.0 dB (key-on, 500 Hz)**: the code's noise setting n gives S₅₀₀ = 24.0 dB − 10·log₁₀ n with n ≤ 199 [inference: arithmetic from code]. The repository reports no CER at all. MaorAssayag's decoder, cited in the research notes with exactly 740,395 parameters and 21 input bins, has the same size and input as nn-morse and is probably derived from it [inference]. **bg4xsd/cwlab** (2022–23, MIT, abandoned) is a lightly modified copy of nn-morse with a 59-symbol alphabet in which two pairs of symbols share a Morse code (`=`/`^` for BT, `$`/`*` for SK), so identical audio carries two labels in training; its results are qualitative only. It is **unrelated to lucpaysan/CW-LAB**, the e04 fork cited under option 4 below; only the names resemble each other. **souryadey/morse-dataset** (Dey, Chugg and Beerel 2018, MIT) holds isolated characters as abstract 64-sample intensity vectors, with no audio, no timing between characters and no physical SNR, so it is unusable as training or benchmark data here [inference].

Cost separates the neural options sharply. VE3NEA's model is estimated at **15–20 million MAC/s per channel**, from its LSTM (about 328,000 MACs per step at about 23 steps/s) and its second convolution. That is about 5–6 GMAC/s for 300 channels, feasible on one desktop core with SIMD. As a single [N × 320] × [320 × 1024] matrix multiply per step, it batches naturally across channels. A Raspberry Pi likely handles only a fraction of that; the number is unmeasured [inference]. The research team timed e04's ONNX model on one thread of an Alder Lake laptop CPU. A 10 s window took 97–474 ms (21–102× real time), and a 30 s window took about 3.2 s. The superlinear growth is consistent with attention. Run as a sliding window refreshed every second, this implies only about 2–10 channels per core [measured, single noisy run with random input; per-channel figure is inference]. morseformer was exported to ONNX (15.9 MB, standard operators only, agreeing with PyTorch to 2.5×10⁻⁶ in probability) and timed on the same class of laptop CPU (an i7-12700H), one thread, fp32. Analytically it costs about 4.2 GMAC per 6 s window, which at one window per 2 s is **about 2.1 GMAC per channel-second, roughly 100–140× option 2's estimate**. A window took 97–106 ms at best and about 280 ms sustained on a performance core, and about 800 ms on an efficiency core or a throttled one: **about 7–20 channels per performance core**, 2–3 per efficiency core, and an estimated 8–20 per Raspberry Pi 5 at full load. Batching did not help, and the best case is already near the core's measured matrix-multiply rate (morseformer-notes.md §7) [measured for the timings; inference for the channel counts and the Pi]. nn-morse, for comparison, costs about 37 million MAC/s per channel, twice DeepCW's estimate, and batches across channels the same way [inference: arithmetic from code]. No source publishes per-channel throughput, latency, or Raspberry Pi results for any neural Morse decoder. Licensing also matters for adoption. VE3NEA's DeepCW is MIT, morseformer is Apache-2.0, and e04's engine is AGPL-3.0 [fact]. The license of AG1LE's morse-wip Bell port was not established [gap].

The ranked recommendation follows from three facts. The largest demonstrated gains are in fading and timing robustness. Sensitivity in steady noise is set mostly by the front end. And CPU across hundreds of channels, especially on a Pi, is a hard constraint.

**1. Soft, pre-filtered front end on the existing baseline (build first, cheapest).** First, re-center each station: estimate its frequency finely, track its drift, and shift its channel so the station sits within a small fraction of 1/T of 0 Hz (for example ±2 Hz). Without this, the ±11.7 Hz bin-rounding offset alone costs up to 5.1 dB at 25 WPM and 8.8 dB at 20 WPM, relative to a centered station, through a dit-matched filter (see the Bell 1975 discussion). Then add a second-stage complex filter matched to the current dit estimate, a few tens of Hz wide, at 1500 samples/s. This is the "two-stage channel filtering" already on the backlog. Convert the envelope into a log-likelihood ratio (LLR) from Rician-versus-Rayleigh densities, using the tracked mark level and noise floor: for a normalized envelope x = R/σ and normalized key-down amplitude a = s/σ (R, s and σ in FS, σ² the noise variance per real component), Λ(x) = −a²/2 + ln I₀(a·x), where I₀ is the modified Bessel function of order zero (the OOK case of Proakis eq. 4.5–21, p. 213; proakis-ook-notes.md §2.2) [fact for the form]. **Caveat:** that LLR is exact for one matched-filter output per element. Consecutive samples of a narrow-filtered envelope at 1500 samples/s are strongly correlated, so summing per-sample LLRs overcounts the evidence by roughly the number of samples per filter correlation time. Scale them down, or decimate to about one sample per 1/B (B the pre-filter's noise bandwidth), before a sequence decoder adds them up (proakis-ook-notes.md item 13) [inference]. Bell's pre-versus-post detection results, his own 6–10 dB estimate for the matched filter over his 100 Hz filter, and fldigi's matched-filter option are the evidence. Cost is a few dozen operations per sample, plus the frequency estimator. The soft output is exactly the emission stream that options 3 and 4 consume, so no work is wasted [inference]. Built in this project as the Matched front end (milestone 2, part 1); its measured gain over the baseline on the synthetic suite is in signal-processing.md §8b [measured].

**2. Small streaming CNN+LSTM-CTC, VE3NEA recipe (the primary challenger).** Reimplement VE3NEA's MIT-licensed model, or retrain it on the project's own port of his generator, using a 128-point FFT with a 16-sample hop on the channel stream. Batch the LSTM step across all active channels and export to ONNX, with int8 quantization as a later option. It has the only controlled evidence of beating a strong Bayesian decoder, and its cost is known to within a factor of about 2. Risks: the gap between synthetic training data and real audio (morseformer), spacing on hand-sent code, worse performance than Skimmer at slow speed, and Raspberry Pi throughput [inference].

**3. Explicit-duration HMM with beam search (the classical challenger).** The state is keystate/element (about 6 classes) × time in state in dit units × a discrete speed grid. The per-channel or per-path Kalman amplitude and noise trackers follow Bell 1977, fed by option 1's likelihoods. Bell's verified design gives the starting parameters: integer speeds of 10–60 WPM changing only at element boundaries, speed-normalized Laplacian durations, pruning to the best path per element type and then to 0.9 cumulative probability, at most 25 paths × 30 successors, and a 1 s decision delay (bell-1977-notes.md §2.2, §4) [fact]. Two changes from Bell are indicated by his own results: a matched pre-filter instead of his 100 Hz filter, and an interference or impulse state, since interference caused his field failures [inference]. Evidence is weaker: Bell's simulations, which reach 3–8% letter error at S₅₀₀ ≈ −1 to −3 dB for random letters at 20 WPM, AG1LE's unstable port, and Skimmer's unpublished success. It earns third place because its costs are low and predictable, and its explicit timing model targets the spacing failures that dominate neural real-audio errors. It also yields calibrated character probabilities for a callsign posterior [inference].

**4. Hybrids, once 2 and 3 exist.** Three designs are worth testing. The first feeds the network's per-frame key-on posteriors into option 3's HMM as its emission probabilities, keeping the HMM's timing model while gaining the network's fading robustness. The second runs CTC beam search with a ham-specific character model: callsign patterns in the spirit of patt3ch.lst, plus CQ/TEST/DE/5NN/TU exchange templates. The third arbitrates: the cheap decoder runs everywhere, and the network runs only on channels with low confidence or detected QSB, capping CPU. morseformer, whose weights are ready and ONNX-exportable, is a ready-made candidate for that expensive second opinion, capped to a handful of channels (morseformer-notes.md §9) [inference]. The research found no quantitative result for any neural-plus-classical fusion in Morse. The closest published systems pair a neural recognizer with an n-gram word splitter ([morseformer](https://github.com/sderhy/morseformer)), or ship a neural and a "traditional Bayesian" decoder side by side without fusing them ([CW-LAB](https://github.com/lucpaysan/CW-LAB)) [fact; the three designs are inference]. Language priors must raise confidence without inventing calls. morseformer's experience with its GPT model is the warning [fact/inference].

**Not first:** e04-class and morseformer-class attention models: about 10× the parameters of option 2 and, measured for morseformer, about 100–140× its compute; whole-window rather than streaming; e04 takes 800 Hz-wide audio and is AGPL. (An earlier version called morseformer PyTorch-bound; it exports cleanly to ONNX.) Also not first: ggmorse, RSCW and SOM matching, whose assumptions (one steady speed, perfect timing, forced nearest match) contradict the skimmer's traffic [inference].

**The ranking after paper verification is unchanged.** The checks against Bell 1977, Proakis, the second batch of six documents, morseformer with three GitHub repositories, and manta changed details, not the order [inference]:

- Option 1 gains a prerequisite (frequency re-centering) and a caveat (correlated likelihoods), but its case is stronger, not weaker. Proakis confirms that the matched filter belongs before the envelope, and Bell independently estimated 6–10 dB lost to a filter 4–10 times wider than matched. It is still the cheapest and the one that feeds every later option.
- Option 2's evidence, VE3NEA's controlled comparison under fading and hand keying, is untouched by either check.
- Option 3's evidence is now primary-source rather than secondhand, and its numbers are sober: about 2% letter error in the idealized case at E/N₀ = 12 dB per dot (not the 10⁻⁵ once relayed), 3–8% in realistic simulation near S₅₀₀ = −2 dB, and failures on real interference. None of these results includes fast fading or compares against a neural decoder on common data. Nothing in them overturns the network's controlled advantage, so it stays third.
- The cost estimate for option 3 moved from about 2.4 to about 2–3 Mflop/s per channel, now grounded in Bell's pruning statistics; the cost comparison with option 2 (15–20 million MAC/s) is unchanged.
- The second batch (Gold 1959, the IEEE 2023 LSTM-CTC paper, AG1LE's 2012 eHam article, Wang 2018, YFDM and G4ILO's blog) changes nothing in the order, because none of the six is a benchmark comparable to the ones the ranking rests on. None reports a CER against an SNR with a stated bandwidth and definition, none tests fading or poor fists against another decoder on common data, and YFDM is a detector, not a decoder. The corrections are to attribution and description: MAUDE's test was 184 messages from 53 operators, not 184 operators, with no noise stated; the weak-signal praise of Skimmer came from a commenter, not G4ILO. MAUDE's order-statistics rules, which fix element classes from Morse structure before any threshold is applied, are a small precedent for option 3's use of code structure, not new evidence for it [inference].
- The morseformer and GitHub-repository checks also leave the order unchanged [inference]. morseformer brings two things option 2 lacks, ready weights and some real-audio evidence, but it loses on exactly the constraints the ranking weighs most: about 100× the compute per channel, no streaming and up to 4 s of latency, a 16–28 WPM training range, and no controlled SNR curve. Its real-audio evidence also shrank on inspection, from 17.75% to 28.6% CER on the held-out operator. It therefore gets a role rather than a rank: a **reference decoder in the benchmark harness now**, since it needs no training, and later possibly an **opt-in, channel-capped second-opinion decoder** under option 4, only if the benchmark shows it beats option 2 on the stations where it would run. It is not a replacement for option 2 and does not come before it. nn-morse, cwlab and morse-dataset report no CER and so carry no evidence; nn-morse is a weaker relative of option 2 at twice the cost.
- The manta check leaves the order unchanged too [inference]. Its `hsmm` decoder is option 3 built and run: its 56.1% versus 26.7% whole-call copy against the threshold-keyed `legacy` decoder on real contest windows is the first real-signal support for option 3 over a threshold-keyed decoder, and so strengthens option 3's case against the baseline. It does not bear on option 2's place, since no neural decoder was scored on the same data, and it does not test option 1's Rician front end, which `hsmm` lacks. Its failures on its own synthetic "real-conditions" and pileup vectors and its CPU cost (4.25× its budget) temper the result. manta's decoder therefore becomes a worked design reference for option 3, and its oracle a method for scenario H, not a change in rank.

The benchmark should reproduce VE3NEA's grid so that his numbers become an external anchor, then add what no source has measured. Every scenario reports CER with spaces scored separately from characters, S₅₀₀ key-on as generated, WPM, and CPU time per channel-second on a desktop and on a Pi 5:

## Conclusion

The evidence overturns a tempting assumption: that the path past a hard-decision decoder is sensitivity, with neural networks as the obvious upgrade. Normalized to key-on SNR in 500 Hz, no published result separates decoders by more than the ambiguity in their SNR definitions in steady noise. The one controlled test shows the small network's advantage is robustness to fast fading and imperfect keying, not a lower threshold. Meanwhile Bell's half-century-old experiments locate most of the recoverable sensitivity in the front end, before any sequence model runs. For this project that means the first measurable win is probably the pre-detection filter and soft likelihoods, which first require each station to be re-centered precisely on its frequency. The real contest is then between two different ways of modeling the channel and the operator, one learned and one explicit.

The open problems are the ones nobody has measured: interference within tens of Hz, abrupt speed changes, real-audio spacing, and throughput on a Raspberry Pi at hundreds of channels. The project's benchmark would be the first public source for all of them. That makes the generator and scoring harness, with the SNR convention written into every result, a more durable contribution than any single decoder. Suppose the hybrid, with network emissions feeding a duration HMM, outperforms both parents. It would then be the first published evidence that the probabilistic pipeline VE3NEA described in 2013 and the neural recognizer he released in 2024 are complements rather than rivals [inference].
